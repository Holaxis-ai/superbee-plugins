# Extending Deep Research without inheriting its Kinds

Install the selected core, then explicitly install a domain recipe that owns new
Kinds. Current recipes do not apply `requires`, `composes` or schema inheritance.
Validation success is not proof a dependency was installed. A disjoint extension
must document prerequisites and test the combined selected definitions.

## Small extension recipe

Copy the example `examples/deep-research/extensions/place-history`. It contains a
manifest, one `Place Comparison` convention and one reference. The comparison
links to common Claims and Observations instead of redeclaring them. Its subject
labels are explicit candidates, not an automatic parcel/address identity match.
The `house-history` starter creates three fictional domain records with the core
evidence graph. See the repository's `examples/deep-research/README.md` for commands.

1. Choose a recurring domain distinction that later queries really need.
2. Give its convention, path and references unique names.
3. Link to core records with declared target Kinds and explained exact labels.
4. Keep canonical assertions/evidence on those core records. A comparison or run
   can add domain context without copying their truth/review state.
5. Demonstrate one complete journey, a counterexample and a later question.
6. Test installation order, repeated installation, typed relationships and base
   convention bytes. Do not treat same-Kind evolution as safe inheritance.

No extra Kind is needed for a new topic or a custom body section. A domain can use
ordinary prose until recurring structured queries justify a convention. A run,
measurement, interview or parcel does not need to pretend it subclasses Observation.

## Optional companion boundaries

- Attempts/coverage when bounded attempts need independent retrieval or reuse.
- Methods/runs when input, procedure, outputs, units and execution identity matter.
- Captures/representations when source revisions and derivative lineage need records.
- Entity/identity models when unresolved equivalence is repeatedly investigated.
- Decisions/assumptions when human authority and planning require their own lifecycle.
- Rounds/readers/collections when coordination or presentation earns another layer.

None is automatically installed. A four-Kind recipe and synthetic examples do not
qualify scientific experimentation, systematic literature review or a publication.

## Existing bundles

Do not retype historical or civic records mechanically. Their consumers may depend
on type names, paths, relationships, temporal fields and IDs. Inventory those
consumers, map semantic loss and rehearse on a disposable copy. Preserve IDs and
original assets; use read-model adapters where useful instead of duplicate
authoritative facts. An instance migration is separate from additive recipe evolution.
